# 对话提炼与执行记忆

更新时间：2026-10-21。

本文件从长期 Creo 自动化对话中提炼可复用的工程知识。它不是聊天原文，也不包含公司 CAD、私密表格或账号信息。实时模型读回、当次明确指令和已批准的项目专用规则优先于本文件。

## 用户最重视的执行方式

- 只报告真实结果；“命令已发送”不等于“执行成功”。
- 使用当前已经打开的 Creo 和已选择的工作目录，避免无必要重启。
- 已做通的能力必须通过正式 MCP / Pro/TOOLKIT 接口执行，不用截图、鼠标、键盘或外部桥接绕过。
- 第一步快速读取会话、顶层装配、骨架和关键特征；后续复用经过核对的语义映射。
- 修改完成后返回顶层装配重新生成、读回并保存。
- 非关键步骤失败时记录真实阻塞，继续其他互不依赖的安全步骤。
- 位置与阵列尺寸默认使用整数；确有产品标准小数时保留标准值。
- 常用已验证操作应在秒级完成，禁止分钟级盲目遍历和反复重试。

## 壁挂改型的关键经验

- 严格按 14 步流程执行，屏模型切换后立即核对“目标屏活动、其他屏隐含”。
- 玻璃同时修改外尺寸和内尺寸；改名必须通过 Creo 模型改名并更新装配引用。
- VESA 数据顺序固定为横向 × 纵向，曾发生长宽写反，写入前后必须按坐标方向分别验证。
- 壁挂草绘宽固定 400 mm，长度按 100 mm 档位，且只能位于指定安装区域。
- 风扇、过滤棉、两组气弹簧和铰链不是尺寸变化后的附加检查，而是改型必做步骤。
- 每一阶段都记录原值、新值、读回值、重新生成结果和耗时。

## 风扇经验与当前能力边界

- 从 55 寸改为 65 寸时，用户曾明确要求：出风仓增加 1 个，进风仓增加 3 个；反向改型只能在确认起始配置确实对应这一方案后，反向减少。
- 2026-10-21 的一次 V16 只读观察中，`M26Z0181080-V01` 含 8 个 `FAN-92X38` 和 8 个 `92-FANGHUWANG`。
- 同次观察中，`M26Z0141001-V01` 含 5 个 `M26Z0181079-V01`，但其是否等同于出风风扇本体尚未由 API 语义验证。
- V16 当时没有安全的“减少组件数量并重新均布”正式工具。只有读取和新增组件接口时，不得用删除零件特征工具冒充风扇阵列修改。
- 风扇适配完成的判定必须包含：进/出风区分、实际成员数、首位、间距、中心对称、顶层重新生成和读回。

## 气弹簧经验

- 每次适配必须同时完成：活动件质量、重心力臂、气弹簧力臂、型号、推力、前后支架位置、关闭压缩余量、最大开启角度和保持力矩。
- 前框目标最大开启角度 50°，允许 ±5°；关闭压缩余量约 10 mm。
- 两根气弹簧要分别验证关门不会自开、最大开启不会下落。
- 后盖支架优先调整；前框支架必要时可小范围调整。两者只改安装位置，不改支架结构拉伸长度。
- 屏组件与前框最大开启状态角度差不得超过 3°。
- 调整约束或装配方向后必须核对开合方向，避免门板反向运动和机构断开。
- 只比较总推力与重量不能证明能够撑起，必须比较绕铰链的力矩。

## 质量读取经验

- Creo 已分配材料的实时质量优先；知识库屏重量只用于公司已确认的标准屏。
- 隐含屏不计入屏组件质量。
- 装配中部分标准件无材料会导致整机质量汇总失败；这不等于连接失败，但不能把不完整汇总报告成真实整机质量。
- 前框和屏组件力学计算应采用明确的活动件组件白名单，不能为了得到数字而忽略所有失败组件。

## 常见故障与处理

- `traceback.log` 自动回溯通常说明原生写入、机构求解或引用处理发生严重错误。先停止写入并核对实际保存状态，不立即重复相同命令。
- “机构断开连接”表示当前约束或几何位置无法同时满足；继续按钮不代表机构已修复。
- 旧入口、旧 DLL 和新 MCP 服务混用会造成工具声明与运行时能力不一致。每次握手必须报告真实协议版本。
- 读取完整尺寸树、组件树或质量失败列表会显著拖慢响应；常规操作只读取目标对象和必要摘要。
- 模型改名、玻璃引用更新、阵列成员数量、机构开合和装配质量属于高风险操作，必须使用专用的可回滚接口。

## 当前优先补齐的正式 MCP 能力

1. 进风仓/出风仓风扇数量、首位、间距和对称性的一次性写入与读回。
2. 装配组件按实例安全隐含、恢复或删除，并自动维护阵列和约束。
3. 前框与屏组件两组气弹簧的闭合/开启运动学、行程、余量和力矩闭环验证。
4. 活动件组件白名单质量与重心读取。
5. 机构失败后的原子回滚。
6. 玻璃安全改名与所有装配引用更新。
7. 铰链阵列数量、种子位置和间距在不同模型版本上的稳定映射。
