# 撤销与常驻桥接

## 现象

启用持续轮询的同步 Pro/TOOLKIT DLL 后，Creo 主界面的撤销按钮可能保持灰色，`Ctrl+Z` 无法撤销已提交操作。

## 原因

同步 Pro/TOOLKIT 调用会影响 Creo 主会话的撤销/重做栈。常驻 DLL 如果通过高频 UI 定时器持续进入 Toolkit，即使没有模型写入，也可能不断清空主撤销栈。

## 当前默认处理

- 默认构建和安装使用随正常 Creo 启动加载的 v14 进程内 DLL，不使用专用启动器。
- 安装脚本默认不写入 `config.pro`；用户显式授权注册时，只在备份后追加独立 DAT 行，不修改 WJT276。
- DLL 不使用 100ms Toolkit UI 定时器；管道收到命令后才向 Creo 主线程投递一条 Windows 消息。
- 空闲期间不会进入 Toolkit，命令执行结束后继续等待；Creo 退出时 DLL 和内部管道同时结束。
- 每个 Creo PID 使用独立管道，避免把命令发送到另一个 Creo 进程。

`max_undo 5` 只能设置撤销深度，不能解决常驻 Toolkit 调用清空撤销栈的问题。

## 安全原则

- 不要为了修复撤销而覆盖用户完整 `config.pro`。
- 不要自动停用、删除或重写 WJT276。
- 修改配置前列出准确行和影响，并获得用户明确许可。
- 保留配置备份，但不要把真实配置上传到 GitHub。
