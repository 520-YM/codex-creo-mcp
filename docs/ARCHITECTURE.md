# 架构说明

## 数据流

1. Codex 通过标准输入输出启动 `mcp/server.cjs`。
2. MCP 服务验证参数、工作目录、模型名、特征名和预期旧值。
3. 首次命令通过常驻桥接读取当前 Creo 会话和工作目录。
4. 原生桥接程序通过 Pro/TOOLKIT 调用 Creo。
5. 修改后重新生成、读回验证并保存；失败时尽量回滚。
6. 旧版本清理只针对本次目标模型族，并移入 Windows 回收站。

## 组件

- `mcp/server.cjs`：60项工具的注册、参数验证、目录边界和进程调度。
- `native/*.c`：Pro/TOOLKIT 原生实现。
- `creo_safe_resident.dll`：Creo 内常驻命名管道服务。
- `creo_sheetmetal_flat_wall_persistent_bridge.exe`：异步会话连接与批量命令通道。
- `scripts/*.ps1`：经过模型身份保护的快捷业务命令。

## 工作目录边界

工具不保存项目根目录，也不接收目录参数。每次 MCP 调用开始时读取 Creo 当前工作目录并缓存到该次调用结束。模型文件必须为该目录的直接子文件，路径分隔符和目录逃逸会被拒绝。

## 两种连接方式

- 常驻 DLL：启动快、命令延迟低，但同步 Toolkit 定时调用可能影响 Creo 撤销栈。
- 异步桥接 EXE：按需连接，启动稍慢，适用于不希望常驻 DLL 的场景。

目前最快工作流使用常驻 DLL，并在 Creo 退出时让会话绑定桥接自动结束。
